## 2. 검색 API 연결하기 (3단계)

어떤 API 든 **한 번 호출하는 예시 요청** 하나만 있으면 됩니다.

1. **요청 보내 보기** — 브라우저 URL, API 문서의 예시, `curl` 명령을 붙여넣습니다. 붙여넣으면 바로 한 번 호출해 **실제 응답**을 아래에 보여 줍니다.
   - **입력 방식**: 요청에 들어 있는 값마다 **바뀌는 값 / 고정 값 / 빼기** 중 하나를 고릅니다. 바뀌는 값(검색어 등)이 비교·평가 화면의 입력칸이 되고, 고정 값은 항상 그대로 보냅니다.
   - 바뀌는 값마다 **입력할 때 보일 이름**과 **필수 여부**를 정합니다. 이름은 자동으로 제안됩니다(`q` → 질문, `keywords` → 키워드, `top_k` → 결과 수, `cat` → 분류). 결과 필드도 `org_nm` → 조직명, `primary_responsibilities` → 주요 담당 업무처럼 제안하며, 판정 모델도 이 이름을 보므로 알아보기 쉬운 이름이 판정에 유리합니다. 필수 값이 비어 있으면 단건 검색 비교는 호출 전에 막고, 평가는 실행 전 검증에서 실패로 표시합니다.
   - API 마다 받는 값이 달라도 됩니다. 예: A 는 `q`+`keywords`, B 는 `q` 만 또는 `q`+`cat`.
   - 같은 이름이 여러 번 나오거나 본문의 배열이면 ‘여러 값’으로 알아보고, 입력할 때 쉼표로 구분합니다.
   - **중첩 JSON 본문**(`{"query": {"text": …, "size": 10}}`)은 `query.text`, `query.size` 처럼 경로별 값으로 펼쳐 보여 주고, 보낼 때 같은 구조로 다시 조립합니다(숫자·참/거짓 타입 유지).
   - **인증**: 필요 없음 / API 키(Bearer) / API 키(헤더). curl 에 키가 있으면 자동으로 채워지고, 키 대신 서버 환경 변수 이름을 쓸 수도 있습니다.
   - 응답 안에서 **결과 목록**(여러 개 항목이 든 배열)을 자동으로 찾습니다. 여러 곳이 보이면 고릅니다.
2. **결과에서 고르기** — 필드마다 **1·2·3번째 실제 결과 값**을 나란히 보면서 쓰임새를 고릅니다.
   - **제목** 1개, **판정에 보냄** 1개 이상(필수), **고유 번호**(같은 결과를 알아보는 값, 권장), 점수(표시만), 안 씀
   - 전화번호·이메일 등 개인정보로 보이는 필드는 자동으로 ‘안 씀’이 되고 표시가 붙습니다.
   - 다른 값으로 다시 불러와 확인할 수 있고, 아래에 **판정 모델이 보게 될 모습**이 나옵니다.
3. **저장** — 이름·메모·대기 시간·인증서 검사를 정하고 정리된 설정을 확인한 뒤 저장합니다.

이미 연결한 API 는 **수정**으로 같은 화면을 다시 엽니다. 경로 변수·헤더를 세밀하게 다뤄야 하면 **개발자용 직접 편집**을 쓰세요.

### 개발자용 직접 편집 참고
| 목록 전달 방식 | 예 (`keywords=[a, b]`) |
|---|---|
| 키 반복 | `?keywords=a&keywords=b` |
| 공백 결합 | `?keywords=a b` |
| 쉼표 결합 | `?keywords=a,b` |
| JSON 배열 | body 의 `"keywords": ["a","b"]` |

| 응답 경로 문법 | 뜻 |
|---|---|
| `results` | 최상위 키 |
| `data.items` | 중첩 키 |
| `assignments[].org_nm` | 배열의 모든 원소에서 값을 모아 ` / ` 로 연결 |
| `items[0].name` | 특정 순번 |
| `$` | 응답 전체(최상위가 배열일 때) |

## 3. 비교 세트 — 요청·응답 형태가 다른 API 도 비교 (4단계)

검색엔진 교체처럼 **ASIS 와 TOBE 의 요청·응답 형태가 다를 때**도 비교할 수 있습니다.

1. **API 고르기** — 이름, 기준(지금 쓰는 것), 비교할 후보(1개 이상). 후보마다 **평가 기준**을 고릅니다 — 각 후보는 자기 평가 기준으로 기준 API 와 견줍니다(예: TOBE 는 ‘담당자 검색 기준’, TOBE2 는 ‘엄격한 기준’). 평가 기준은 평가 기준 메뉴에서 만든 목록에서 고르며, 없으면 ‘여기서 바로 만들기 +’로 화면을 떠나지 않고 만들어 바로 선택할 수 있습니다(평가의 판정 방법 단계에서도 같음). API 가 딱 2개면 기준·후보가, 평가 기준이 1개면 그 기준이 미리 골라집니다.
2. **입력 맞추기** — API 설정을 보고 자동으로 맞춘 결과를 ‘입력을 자동으로 맞췄습니다’ 요약(입력마다 공통/전용, API 별로 어느 값에 들어가는지)으로 보여 줍니다. 그대로 다음으로 가면 되고, ‘직접 고치기’를 누르면 아래 세부 설정이 열립니다. 입력은 두 종류입니다.
   - **공통 입력**: 모든 API 에 보내는 값(예: 질문). 여러 API 에 같은 뜻의 값이 있을 때 하나로 묶입니다.
   - **API 전용 입력**: 한 API 에만 보내는 값(예: A 전용 `keywords`, B 전용 `분류`). 키는 `A__keywords` 처럼 API 라벨이 앞에 붙습니다.
   - API 를 다 고르면 **API 설정의 입력 방식을 보고 자동으로 나눕니다**: 이름이 같거나 비슷한 값(q·query·text, keyword·keywords, size·limit·top_k …)이나 예시 값이 같은 값은 공통으로, 한 API 에만 있는 값은 그 API 전용으로. 어느 API 에서든 필수면 입력도 필수(*)가 됩니다. ‘API 설정에서 자동으로 다시 나누기’로 언제든 다시 할 수 있습니다.
   - 입력마다 범위(모든 API 공통 / ○○ 전용)를 바꿀 수 있고, API 별 연결에서 ‘+ 이 API 전용 입력 새로 만들기’로 바로 추가할 수 있습니다.
   - 단건 검색 비교 입력칸, 테스트 데이터 열, 판정 모델이 읽는 입력 이름이 모두 이 입력들입니다(전용 입력은 ‘B 전용 · 분류’ 처럼 표시).
   - **API 별 연결**: API 의 바뀌는 값마다 **가져올 곳**(공통 입력 / 항상 같은 값 / 조합 문장 / 보내지 않음)과 **변환**을 고릅니다.

     각 API 의 연결 목록에는 공통 입력과 **그 API 의 전용 입력만** 나옵니다. 필수 값을 ‘보내지 않음’으로 두면 빨간색으로 알려 줍니다.

     | 변환 | 예 |
     |---|---|
     | 그대로 | `q` → `query` |
     | 공백으로 합치기 · 쉼표로 합치기 | `[학자금, 교육비]` → `"학자금 교육비"` |
     | 목록으로 나누기 | `"학자금 교육비"` → `[학자금, 교육비]` |
     | 첫 번째 값만 | `[a, b]` → `a` |
     | 숫자로 | `"5"` → `5` (JSON 본문) |
     | 조합 문장 | `{q} {keywords}` → `"학자금 담당 학자금 교육비"` |

     자동으로 나눌 때 연결과 변환(형식이 다르면)도 함께 골라 둡니다.
3. **결과 맞추기** — 두 API 결과 중 ‘같은 결과’를 알아보는 기준.
   - **고유 번호로**(권장): API 마다 대소문자 무시, 숫자만 비교, 앞·뒷부분 지우기(예: `EMP-E101` → `E101`)로 형식을 맞춥니다.
   - **제목으로**: ID 체계가 전혀 다를 때. 띄어쓰기·기호·대소문자를 무시하고 비교합니다.
   - **같게 보지 않음**: 각각 판정만 하고 순위 변화·겹침은 계산하지 않습니다.
   - API 마다 판정에 보내는 내용이 다르면 경고합니다(정보가 많은 쪽이 유리할 수 있음).
4. **확인해 보기** — 같은 입력으로 실제로 불러, API 별로 **보낸 값**·요청 본문과 **기준과 겹치는 결과**를 보여 줍니다. 겹침이 0이면 ‘같은 결과’ 규칙을 확인하라고 알려 줍니다.

기존 비교 세트는 아무것도 바꾸지 않아도 이전처럼(같은 이름의 값을 그대로) 동작합니다.

## 4. 평가 기준 — 질문에 답하듯 정하기
1. **무엇을 찾는 검색인가요?** — 일반 검색·사람·조직/창구·문서/지식·상품·직접 쓰기 중 고르면 검색 목적 문장이 채워집니다. 우리 서비스에 맞게 고쳐 쓰세요.
2. **얼마나 엄격하게 볼까요?** — 느슨하게(약간 관련 이상) / 보통(관련 이상, 권장) / 엄격하게(매우 관련만).
3. **상위 몇 개까지 볼까요?** — 실제 화면·에이전트가 보여 주는 결과 수와 맞춥니다.
4. **추가로 지킬 조건** — 한 줄에 하나씩. 예시를 눌러 바로 넣을 수 있습니다.
5. **두 결과 목록도 통째로 비교할까요?** — 켜면 결론의 보조 근거가 생기고, 끄면 판정 호출이 줄어듭니다.

판정 모델에 실제로 보내는 프롬프트는 편집 화면 아래 ‘프롬프트 보기’에서 확인할 수 있습니다. **고급 설정 · 판정 프롬프트**를 열면 기본 원문(시스템·항목 판정·목록 비교)을 보고 직접 고칠 수 있습니다(자리 표시자 버튼, 저장 전 오류 검사, ‘기본값으로’ 되돌리기).

## 5. 테스트 데이터

만드는 방법은 세 가지입니다(화면 위쪽 카드).
- **LLM 으로 만들기 (추천)** — 아래 ‘LLM 으로 만들기’ 참고.
- **파일 올리기** — CSV(UTF-8·CP949 자동 인식), TSV, XLSX(첫 시트), JSONL, JSON 배열. 첫 줄은 열 이름, 최대 5,000행·10MB. ‘양식 받기’는 사람이 읽는 열 이름(`케이스`, `분류`, `질문`, `TOBE 전용 · 분류`, `기대 정답`)으로 된 CSV 를 줍니다.
- **직접 입력** — 비교 세트의 입력 칸으로 된 빈 표를 만들고 연결까지 저장합니다.

### 비교 세트와의 연결
- 데이터는 **어느 비교 세트에 쓰는지와 열 연결을 기억**합니다. 템플릿·직접 입력·붙여넣기·LLM 생성으로 만들면 처음부터, 파일로 올린 데이터는 처음 평가할 때 쓴 연결이 저장됩니다.
- 목록 위 ‘어느 비교 세트로 평가하나요?’에서 세트를 고르면 데이터마다 상태가 붙고 바로 쓸 수 있는 것부터 정렬됩니다.
  - **바로 사용**(초록): 모든 입력에 맞는 열이 있음(저장된 연결이면 그대로 씀)
  - **연결 확인**(주황): 비슷한 이름의 열로 연결했거나 선택 입력에 맞는 열이 없음 — 평가 화면에서 한 번 확인하면 저장되어 ‘바로 사용’이 됨
  - **필수 열 부족**(빨강): 필수 입력에 맞는 열이 없음 — ‘고치기’로 이동
- 자동 연결 규칙: 입력 key·보이는 이름·‘○○ 전용 · 이름’ 표기를 공백·기호·대소문자 무시하고 비교 → 없으면 비슷한 이름(q·query·질문·검색어, keyword·키워드, size·top_k·결과수 …, 단수·복수). 메타 열(`case_id`/`케이스`, `category`/`분류`, `expected`/`기대 정답`)은 따로 찾습니다.
- **데이터 상세** 화면 위 ‘비교 세트 연결’에서 입력마다 연결된 열(정확히 같음 / 비슷한 이름 / 저장됨)을 보고, ‘빠진 필수 열 추가’, ‘이 연결 저장’을 할 수 있습니다. 표 머리글에는 열이 어떤 입력이 되는지(→ 질문 *), 필수 입력이 빈 칸은 빨간색으로 표시됩니다. 저장하면 연결도 함께 저장됩니다.
- **버전**: 저장할 때마다(화면 수정·파일 올림·LLM 생성·단건 비교에서 추가·되돌리기) 그때 내용이 새 버전으로 남습니다(내용이 같으면 남기지 않음, 최근 30개). 데이터 상세의 **‘vN · 변경 이력’**에서 버전마다 추가·삭제·바뀐 행(바뀐 칸은 이전 → 이후)을 보고, 옛 버전으로 **되돌릴** 수 있습니다(되돌린 것도 새 버전). 평가는 실행할 때의 버전을 기록해 결과·실행끼리 비교 화면에 ‘테스트 데이터 vN’으로 보여 줍니다.
- **단건 검색 비교**에서 결과를 본 뒤 **‘테스트 데이터에 추가’**로 그 입력을 기존 데이터(연결된 열에 맞춰) 또는 새 데이터에 한 줄로 더할 수 있습니다(기대 정답 힌트·분류 선택).
- 비교 세트 목록에는 연결된 테스트 데이터 수가 나오고, 누르면 그 세트 기준으로 데이터 목록이 열립니다.

### LLM 으로 만들기
테스트 데이터 › **LLM 으로 만들기**(또는 평가 › 테스트 입력 › ‘LLM 으로 만들기’, ⌘K ‘테스트 데이터 LLM 으로 만들기’).
1. **설정** — 비교 세트(채울 입력 칸이 정해짐), 서비스 설명(평가 기준의 검색 목적으로 미리 채움), 분류(선택, 분류마다 고르게), 개수(10·30·50·100 또는 직접, 최대 500), 말투 비율(키워드형·자연어 질문·조건 여러 개·오타/구어체·모호한 질의), 만들 모델(판정 모델 목록, 판정과 다른 계열 권장). ‘미리 5개 만들어 보기’로 방향을 먼저 볼 수 있습니다.
2. **정확도 높이기(선택) — 실제 검색 결과 참고** — 켜면 ① 탐색 질의로 모든 API 를 불러 실제 결과 항목을 모으고(API 마다 번갈아 뽑아 한쪽에 유리하지 않게), ② 그 항목이 답인 질의를 사용자의 말로 쓰게 하고(문서 문구 그대로 베끼지 않게), ③ 만든 질의로 다시 검색해 원본 항목이 어느 API 상위에 나오는지·결과 0건인지 표시합니다. 검색 API 호출이 추가되고 시간이 더 걸립니다.
3. **만드는 중** — 서버에서 진행(화면을 떠나도 계속), 단계·진행률·비용 표시, 멈추기 가능.
4. **검토하고 저장** — 만든 질의·걸러낸 것(중복·개인정보·형식)·답 확인 현황·비용을 보고, 표에서 바로 고치거나 행을 빼고(‘결과 0건 모두 빼기’), 이름을 정해 저장합니다. 저장하면 비교 세트와 연결까지 저장되어 **‘이 데이터로 바로 평가’**로 이어집니다.

만든 데이터에는 ‘LLM 생성(· 검색 기반)’ 표시와 생성 설정(모델·설명·말투·분류)이 남고, 열에 `표현 방식`, (검색 기반이면) `원본 항목`, `답 확인`이 함께 저장됩니다. 생성 비용은 운영 › 비용에 ‘데이터 생성’으로 함께 집계됩니다. 합성 데이터이므로 결과를 보고할 때 그 점을 밝히고, 가능하면 실제 질의와 섞어 쓰세요.

## 6. 평가 (5단계)
1. **무엇을 비교할까요** — 비교 세트 선택.
2. **테스트 입력** — 네 가지 중 편한 방법(비교 세트 기준으로 ‘바로 사용’ 가능한 데이터가 몇 개인지 함께 보입니다):
   - **저장된 테스트 데이터**: 목록에 ✓ 바로 사용 / △ 연결 확인 / ✕ 필수 열 부족이 붙고, 저장된 연결이 있으면 그대로 씁니다. 평가를 시작하면 이번 연결이 데이터에 저장됩니다.
   - **LLM 으로 만들기**: 생성 화면으로 이동해 만들고, 저장 후 ‘이 데이터로 바로 평가’로 돌아옵니다.
   - **직접 입력·붙여넣기**: 입력 항목마다 열이 있는 표에 적습니다. 엑셀·메모장에서 여러 줄을 복사해 첫 칸에 붙여넣으면 한 번에 채워지고, 탭으로 나뉜 열은 오른쪽 칸으로 들어갑니다. ‘기대 정답’ 열은 선택입니다.
   - **파일 올리기**: CSV·엑셀·JSONL.
   - (연결 확인) 각 입력이 어느 열에서 오는지 보여 주고(비슷한 이름으로 연결된 것은 주황), 필요하면 ‘연결 바꾸기’로 고칩니다.
3. **입력 검증** — 실행 전에 모든 행으로 API 별 실제 보낼 값을 만들어 보고 검사합니다(호출은 하지 않음).
   - 필수 입력이 비었는지, 숫자 입력이 숫자인지, 각 API 가 필수로 정한 값이 변환 후에도 채워지는지.
   - 전체·통과·실패 행 수, **입력별 채움 현황**(연결된 열, 채워진/빈 행 수), **실패한 행과 이유**(예: `4행 — TOBE 전용 · 분류 이(가) 비어 있습니다.`)를 보여 줍니다.
   - 실패가 있으면 **고친 뒤 다시 검사** 하거나 **실패한 N행은 빼고 실행** 중 하나를 골라야 다음으로 넘어갑니다. 통과한 행이 없으면 진행할 수 없습니다.
   - 서버도 실행을 만들 때 같은 검증을 다시 하므로, ‘빼고 실행’을 고르지 않으면 실패한 행이 있는 실행은 만들어지지 않습니다.
4. **판정 방법** — **판정 묶음 크기**(1개씩 = 정확도 우선 … 12개 = 기본 … 20개 = 비용 우선, 화면에 설명과 예상 호출 수), **후보마다 평가 기준**(비교 세트에 정한 기준이 미리 골라져 있고, 이번 실행만 바꿀 수 있음), 판정 모델, **비용 상한**(선택, USD), 동시 처리 수, 일부만 먼저 해 보기. 후보가 둘 이상이고 기준이 다르면 결과 화면에서 후보마다 어떤 기준으로 채점했는지 함께 보여 줍니다.
5. **확인하고 시작** — “TOBE 가 ASIS 보다 나은지 N개 입력으로 확인합니다” 같은 문장과 예상 호출 수를 보고 시작합니다.

실행은 **서버에서** 진행됩니다. 브라우저를 닫아도 계속되고, 다시 들어오면 진행 상황과 중간 결과가 보입니다.

| 상황 | 동작 |
|---|---|
| 취소 | 진행 중인 작업을 멈추고, 완료된 케이스로 결과를 냅니다 |
| 서버 재시작 | 진행 중이던 실행이 ‘중단됨’으로 표시됩니다 |
| 비용 상한에 닿음 | 남은 케이스를 시작하지 않고 ‘취소됨’으로 멈춥니다. 이미 처리 중이던 케이스는 끝까지 가므로 상한을 조금 넘을 수 있습니다. 판정 모델에 단가가 있어야 동작합니다 |
| 이어서 실행 | 완료되지 않은(오류 포함) 케이스만 다시 처리합니다. 이미 받은 응답·판정은 재사용합니다. 비용 상한으로 멈춘 실행은 상한을 풀고 이어갑니다 |
| 같은 설정으로 다시 | 현재 저장된 설정으로 새 실행을 만듭니다 |

## 7. 결과 읽기
- **요약**: 결론 배너 → 핵심 지표 → **한눈에 보기**(지표 비교 막대, 목록 비교 도넛) → **결과의 질**(1위·상위 k 등급 분포) → **속도와 안정성**(응답 시간, 실패·0건) → 대상별 지표 표 → 케이스별 변화 차트(막대를 누르면 상세) → 분류별(차트·표) → 지표 해석.
- **점수 기준**(요약 위): LLM 판정 / 결합(사람 판정 우선) / 사람 판정. 사람 검수가 없으면 LLM 판정만 나옵니다.
- 결론이 나왔지만 케이스가 30건보다 적으면 **‘근거 약함’** 표시가 붙습니다(10건 미만은 보류). 평가 시작 전 확인 단계에서도 30개 미만이면 경고합니다.
- **Hit@1** 칸에 **1위 평균 등급**(0~3)을 함께 보여 줍니다. nDCG 는 ‘이번에 찾은 결과 중 최선’ 대비 점수라 양쪽 모두 맞는 결과가 적어도 높게 나올 수 있어, 그런 경우 이유를 설명하는 안내가 나옵니다.
- **통계 상세**(기본 접힘, 한 줄 요약 표시): 순열 검정 p(후보가 여럿이면 Holm 보정), 효과 크기, 필요한 케이스 수, 승률·Hit@1 차이의 95% 구간.
- **사람 검수**: 위쪽에 LLM–사람 일치도(가중 카파·관련/비관련 카파·완전 일치·LLM 이 후한 정도·교차표), 아래에서 케이스를 무작위 순서로 채점(0~3 키, ↑↓ 항목, ←→ 케이스, 목록 선호). 30건 정도 검수를 권장합니다.
- **공유**: 실행 결과 위 ‘공유’ → 유효 기간(7·30·90일·기한 없음)을 고르고 링크를 만들면 복사됩니다. 받는 사람은 로그인 없이 결과만 봅니다(설정 세부는 안 보임). 링크마다 조회 수를 보고 끌 수 있습니다.
- **실행끼리 비교**: 평가 실행 기록에서 왼쪽 칸으로 2~6개를 고르고 ‘나란히 비교’(또는 실행 결과의 ‘다른 실행과 비교’). nDCG 차이와 신뢰구간 막대, 지표 표(가장 좋은 값 강조), 조건 표(다른 조건은 주황 + 경고)를 보여 줍니다. 같은 테스트 데이터로 돌린 실행 2개면 **케이스별 변화**(나아짐·나빠짐·목록 비교 판정이 바뀐 케이스)도 봅니다.
- **케이스**: 후보 승·기준 승·무승부·순서 불일치·분류·상태 필터, nDCG 차이 정렬, 검색. 행을 누르면 대상별 결과·항목 등급·판정 근거·두 번의 목록 비교 판정이 열립니다.
- **실행 설정**: 실행 시점의 설정 사본(이후 설정을 바꿔도 결과는 그대로).
- **내보내기**: 엑셀(요약·케이스·항목 판정·목록 비교·설정 시트), CSV(케이스 단위), JSON(전체).
