# 평가 방법 — 어떻게 채점하고, 지표가 무엇을 뜻하나

## 1. 한 케이스를 평가하는 순서

```
질의 ─▶ 모든 대상 호출 ─▶ 상위 k 항목을 key 로 모음(풀) ─▶ 항목별 관련도 판정(0~3)
                                                          │
                                   대상별 nDCG·Hit@1·MRR·P@k ◀┘
후보 × 기준 목록 비교 ─▶ (기준=A,후보=B) + (후보=A,기준=B) 두 번 ─▶ 일치하면 승자, 엇갈리면 무승부
```

1. **대상 호출** — 비교 세트의 모든 대상에 같은 입력을 보내고, 응답 매핑으로 항목 목록을 만듭니다.
2. **항목 관련도 판정(주 판정)** — 모든 대상의 상위 k 항목을 항목 ID 로 모아 **같은 항목은 한 번만** 판정합니다. 어느 대상에서 나왔든 같은 등급이므로 비교가 공정하고 비용도 줄어듭니다. 항목이 12개를 넘으면 나눠서 묻습니다.
3. **지표 계산** — 등급과 순위로 대상별 지표를 계산합니다(수식이라 같은 판정이면 항상 같은 값).
4. **목록 비교(보조 판정)** — 후보와 기준 목록을 통째로 보여 주고 더 유용한 쪽을 묻습니다. A·B 순서를 바꿔 두 번 묻고 엇갈리면 무승부로 처리합니다.
5. 이미 판정한 항목·쌍은 **다시 묻지 않습니다**(이어서 실행 시 비용·재현성).

## 2. 벤치마킹한 방법

| 요소 | 근거 | 이 도구에서 |
|---|---|---|
| 등급 관련도 0~3 | TREC 검색 평가의 표준 등급 관련도 | 3 매우 관련 · 2 관련 · 1 약간 관련 · 0 무관 |
| LLM 이 관련도 판정 | UMBRELA (Upadhyay et al., 2024), Thomas et al. (2023, Bing) — LLM 판정이 사람 평가자와 높은 일치도 | ‘의도 파악 → 일치도·신뢰도 → 등급’ 절차를 프롬프트에 명시 |
| 근거 먼저, 점수 나중 | 사고 과정을 먼저 쓰게 하면 즉흥 판정이 줄어듦 | 출력 스키마에서 reason 이 grade 보다 앞 |
| 쌍대 비교 + 순서 교대 | MT-Bench (Zheng et al., 2023) — LLM 판정의 위치 편향 보정 | 두 번 묻고 엇갈리면 무승부, ‘순서 불일치’로 집계 |
| 풀링 기반 nDCG | TREC 풀링 — 참여 시스템이 찾은 항목으로 이상적 순서 구성 | 같은 케이스에서 모든 대상이 찾은 항목의 등급으로 IDCG 계산 |
| 대응 표본 부트스트랩 | 검색 시스템 비교의 표준 유의성 확인 | 케이스별 nDCG 차이의 평균에 대한 95% 신뢰구간(2,000회) |
| 부호 검정 | 승패 데이터의 간단한 유의성 검정 | 무승부 제외, 정확 이항 양측 p-값 |

## 3. 프롬프트 구성

```
[시스템]      공용 — 평가자 역할, JSON 만 출력
[평가 과제]   공용
[검색 목적]   평가 기준에서 작성(비우면 공용 문장)
[관련도 척도] 공용 고정
[판정 절차·원칙] 공용 고정
[기대 정답 힌트] 데이터셋 expected 컬럼(있을 때만, 참고용)
[사용자 요구사항] 평가 기준에서 작성(있을 때만, 공용 원칙과 함께 반영)
[질의]        케이스 입력
[항목 / 결과 A·B] 응답 매핑에서 고른 필드만
```

설정 → 평가 기준 편집 화면에서 최종 프롬프트를 미리 볼 수 있습니다.

## 4. 지표 사전

| 지표 | 정의 | 읽는 법 | 알 수 있는 것 |
|---|---|---|---|
| **nDCG@k** | 상위 k 의 등급을 순위 가중(1/log₂(순위+1))으로 합산 ÷ 이상적 순서의 점수 | 0~1, 클수록 좋음. 정답이 아래 있으면 깎임 | 순위 품질 전반 — 가장 기본 지표 |
| **nDCG 차이** | 케이스별 (후보 − 기준) nDCG 의 평균 | +면 후보 우세. 95% 신뢰구간이 0을 포함하면 우연일 수 있음 | 개선 폭과 그 확실성 |
| **Hit@1** | 1위 항목이 ‘관련’(기준 등급 이상)인 비율 | 첫 결과만 보고 답을 얻는 비율 | 에이전트·챗봇처럼 1위만 쓰는 곳의 체감 품질 |
| **MRR** | 첫 관련 항목 순위의 역수 평균 | 1위=1, 2위=0.5 … 없으면 0 | 정답이 아래에 묻히는 문제 |
| **Precision@k** | 상위 k 중 관련 항목 비율(분모는 항상 k) | 높을수록 잡음이 적음 | 여러 개를 보여 주는 화면의 목록 깔끔함 |
| **목록 비교 승률** | 승 ÷ (승 + 패), 무승부 제외 | 50% 초과면 후보 우세, 부호 검정 p<0.05 면 유의 | 지표로 표현하기 어려운 전체적인 쓸모 |
| **순서 불일치** | A·B 순서를 바꿨을 때 판정이 달라진 케이스 수 | 많으면 차이가 미미하거나 판정 모델이 흔들림 | 판정 안정성(판정 모델·기준 점검 신호) |
| **실패율·0건 비율** | 호출 실패, 결과 0건 비율 | 0%가 정상 | 품질 차이가 장애 때문인지 |
| **응답 p50·p95** | 성공한 호출의 응답 시간 중앙값·상위 5% | p95 증가는 일부 질의 지연 | 품질 개선이 속도 저하를 동반하는지 |

### 특수한 경우
- **호출 실패**: 그 대상의 지표는 0으로 계산합니다(사용자는 아무것도 못 받았으므로). 목록 비교는 실패하지 않은 쪽 승으로 자동 처리합니다. 양쪽 모두 실패한 케이스는 품질 비교에서 제외하고 실패율로만 보고합니다.
- **관련 항목 없음**: 어느 대상도 관련 항목을 못 찾으면 nDCG 를 정의할 수 없어 평균에서 제외합니다. 절반 이상이면 결과 화면에 경고가 뜹니다.
- **평가 범위 밖 항목**: 상위 k 밖의 항목은 판정·지표에 쓰지 않습니다(화면에 흐리게 표시).

## 5. 결론 규칙

| 결론 | 조건 |
|---|---|
| 개선 | nDCG 차이 95% 신뢰구간의 하한 > 0 |
| 저하 | 상한 < 0 |
| 차이 없음 | 신뢰구간이 0을 포함 |
| 판단 보류 | 관련 항목이 있는 케이스가 10건 미만 |
| 데이터 없음 | 비교할 수 있는 케이스가 없음(전부 실패 등) |

| (후보가 여럿) 보정 후 차이 없음 | 신뢰구간은 0을 벗어났지만 Holm 보정 순열 검정 p ≥ 0.05 |

결론 문구에는 목록 비교 승패도 함께 적습니다. 두 근거가 같은 방향이면 결론을 더 믿을 수 있습니다.

### 통계 상세 (결과 화면 ‘통계 상세’)

| 항목 | 계산 | 읽는 법 |
|---|---|---|
| 순열(무작위화) 검정 p | 케이스별 nDCG 차이의 부호를 무작위로 뒤집어 평균 차이의 분포를 만들고, 실제 이상이 나온 비율. 16건 이하는 전수, 300건 이하는 5,000회, 그 이상은 정규 근사 | < 0.05 면 우연으로 보기 어려움(Smucker 외 2007 권장) |
| Holm 보정 p | 후보별 p 를 Holm–Bonferroni 로 보정 | 후보가 여럿일 때 이 값으로 판단 |
| 효과 크기 d_z | 평균 차 ÷ 차의 표준편차 | 0.2 작음 · 0.5 중간 · 0.8 큼 |
| 필요한 케이스 수 | ((1.96 + 0.84) × 표준편차 ÷ \|평균 차\|)² | 지금 건수보다 크면 케이스를 늘려야 함 |
| 승률 95% 구간 | 무승부 제외 승률의 윌슨 구간, 무승부를 반으로 친 승률도 함께 | 하한이 0.5 보다 크면 후보 우세 |
| Hit@1 차이 95% 구간 | 케이스별 Hit@1 차이의 부트스트랩 구간 | 0을 포함하면 1위 정답률 차이는 불확실 |

## 사람 판정 · 결합 점수 · 일치도

- **사람 검수**(실행 결과 › 사람 검수 탭): 무작위 순서(시드 고정)로 케이스를 보여 주고, 항목마다 0~3 등급(키보드 0~3), 후보마다 목록 선호(기준이 낫다 / 비슷 / 후보가 낫다)를 매깁니다. 기본으로 LLM 판정을 숨깁니다(앵커링 방지). 같은 항목은 어느 목록에서 채점해도 한 번에 반영됩니다.
- **점수 기준 전환**(요약 탭 상단):
  - **LLM 판정** — 판정 모델만으로 낸 결과(기존).
  - **결합** — 항목마다 사람 등급이 있으면 사람 것, 없으면 LLM 것으로 지표를 다시 계산(목록 선호도 같은 방식). 검수할수록 사람 기준에 가까워집니다.
  - **사람 판정** — 사람이 풀(평가 범위의 모든 항목)을 다 채점한 케이스만으로 계산. 10건 미만이면 결론 보류.
- **일치도**: 둘 다 채점한 항목만 비교합니다. 이차 가중 카파(0~3), 관련/비관련 카파(관련 기준 등급 기준), 완전 일치율·±1 이내 일치율, LLM−사람 평균 등급 차(+면 LLM 이 후함), 등급 교차표, 목록 선호 일치율. 카파 0.6 이상 상당히, 0.8 이상 거의 완전 일치(Landis & Koch). 30건 이상 검수를 권장합니다.
- **여러 명이 검수**: 검수자마다 따로 저장합니다(계정으로 로그인하면 계정 이름, 아니면 화면에서 입력한 이름). 사람·결합 점수는 검수자들의 **합의**(항목 등급 = 중앙값, 짝수면 평균을 반올림 / 목록 선호 = 다수결, 동률이면 ‘비슷’)를 씁니다. 검수 순서는 ‘내가 안 본 것’, ‘겹쳐 보기’(다른 사람이 본 케이스 먼저 → 검수자 간 일치도), ‘아무도 안 본 것’(나눠서 넓게) 중에서 고릅니다. 결과에 **검수자 간 일치도**(쌍마다 이차 가중 카파·완전 일치율, 5개 이상 겹친 쌍의 평균, 목록 선호 일치율)와 **검수자별 통계**(케이스·항목 수, LLM 과의 카파, LLM 이 후한 정도)가 나옵니다. 검수 중에는 LLM 과 다른 검수자의 등급을 숨기는 것이 기본입니다.
- 내보내기(엑셀) 요약 시트에 LLM / 결합 / 사람 비교와 일치도가, 항목 판정 시트에 사람 등급·메모가 함께 들어갑니다.

## 판정 묶음 크기

한 번의 판정 호출에 넣는 항목 수입니다(평가 › 판정 방법). 기본 12개, 선택지 1·4·8·12·20.
- **1개씩**: UMBRELA·Bing 연구와 같은 방식. 다른 항목의 영향을 받지 않아 가장 정확하지만 호출이 많습니다.
- **묶음**: 호출이 적고 빠르지만 함께 본 항목이 기준점이 될 수 있습니다. 묶기 전에 항목 순서를 섞습니다(항목 key 로 시드를 정해 재현 가능).

## 판정 프롬프트 고급 설정

평가 기준 편집 › ‘고급 설정 · 판정 프롬프트’에서 시스템 프롬프트·항목 판정·목록 비교 원문을 고칠 수 있습니다(비우면 기본값). 자리 표시자: 항목 판정 `{task_context} {grade_scale} {expected_section} {requirements_section} {query_block} {count} {items_block}`(필수 `{query_block}`·`{items_block}`), 목록 비교 `{task_context} {k} {expected_section} {requirements_section} {query_block} {a_status} {a_block} {b_status} {b_block}`(필수 `{query_block}`·`{a_block}`·`{b_block}`). 글자 그대로의 중괄호는 `{{ }}`. 오타·누락은 저장 전에 막습니다. 바꾼 뒤에는 사람 검수로 일치도를 다시 확인하세요.

## 설계 근거와 참고 문헌

화면의 **도움말 › 평가 방법** 아래쪽 ‘왜 이렇게 만들었나’에 결정마다 이유·참고 연구·검토한 대안, 알려진 한계, 참고 문헌 23편을 정리했습니다(TREC·nDCG·Bing/UMBRELA·MT-Bench·G-Eval·LLM 판정 비판 연구·Smucker 외 검정 비교·Holm·Wilson·Cohen 카파·Landis & Koch·PPI/ARES 등).

## 6. 믿을 만한 결과를 얻으려면
- 케이스 **30건 이상**(변경이 영향을 주는 질의 + 평소 질의를 섞어서).
- 평가 기준의 **검색 목적**에 무엇이 정답인지 구체적으로 적기.
- 최종 결론용 실행은 **성능 좋은 판정 모델**로. 순서 불일치가 많으면 모델 교체·기준 구체화.
- 결과 일부를 **사람이 검수**하고, 동의하지 않는 판정은 사용자 요구사항으로 보정한 뒤 다시 실행.
- 비교하는 시스템과 같은 계열의 모델로 판정하면 자기 선호 편향이 생길 수 있으니 가능하면 다른 계열을 쓰기.
